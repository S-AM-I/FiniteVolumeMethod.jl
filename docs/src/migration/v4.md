# v4.0 Migration Guide

v4.0.0 is a breaking release. It replaces the earlier v2 and v3 migration
notes, which described intermediate states of the same overhaul and are no
longer useful on their own.

Three things changed at once: the package was split into real submodules, the
export surface was curated down from roughly a thousand names to a few hundred,
and the collocated incompressible family was aligned with the SciML problem /
algorithm / solution contracts. Alongside that, several genuine solver defects
were fixed — those change numbers, not just names, and are listed separately
below.

## Results that change

These are behavioural fixes, not renames. If you have stored results from a
previous version, expect them to differ.

- **Momentum-operator ordering (radiation and combustion solvers).** `A_P` was
  extracted from the momentum equations *before* under-relaxation, so the
  diagonal was un-relaxed and `D = V / A_P` was inflated by `1/α_U` (≈1.43 at
  the default). `D` feeds both the pressure-correction Laplacian and the
  Rhie-Chow face flux, so the *converged* flux field was affected, not merely
  the convergence rate. Operators are now extracted after the relaxed solve.

- **Cyclic (periodic) boundary conditions now apply on the thermal, radiation,
  combustion, VOF and ALE paths.** Those loops previously applied no
  cross-boundary coupling, so a `CyclicBC` silently degenerated to its
  `Neumann(0)` expansion — a periodic problem quietly lost its periodicity.

- **Reacting flow with a radiation model now throws instead of dropping it.**
  No reacting-flow solver accepts a radiation model; the old keyword-based
  dispatch selected the combustion branch and discarded the radiation
  arguments, which for a flame usually removes the dominant heat-loss term.

- **Transient runs no longer report `converged = true` unconditionally.** The
  flag was hardcoded in four transient loops, masking NaN/Inf blow-ups. It now
  reports whether the run completed with finite residuals.

- **`SciMLStructures.Tunable` round-trips correctly for `PISO`.** `PISO`
  advertised five tunables but three of them echoed `nu`, and writes to those
  slots were discarded. The schema is now filtered to the parameters the
  algorithm actually has.

## Physics is composed, not passed as keywords

Optional physics used to be supplied as keyword arguments to `solve`. It is now
carried by the problem as an `IncompressibleModel`.

```julia
# before
solve(prob, SIMPLE();
      thermal_props = props, bcs_T = bcs_T, T_init = 300.0,
      turb_model = StandardKEpsilon(), turb_bcs = turb_bcs)

# after
model = IncompressibleModel(
    thermal    = ThermalComponent(props; bcs = bcs_T, T_init = 300.0),
    turbulence = TurbulenceComponent(StandardKEpsilon(); bcs = turb_bcs),
)
prob = SteadyIncompressibleProblem(mesh, bcs, SIMPLE(); nu = ν, model = model)
solve(prob, SIMPLE())
```

Each component takes its own boundary conditions as a **mandatory** keyword, so
"properties supplied but boundary conditions forgotten" is now unrepresentable
rather than caught at solve time. Component dependencies (radiation requires
thermal; radiation and combustion cannot be combined) are validated when the
model is constructed.

`solve` itself now carries numerics only: `linear_solver`, `solver_config`,
`scheme`, `blend`, `tspan`, `dt`, `save_every`, `U0`, `p0`, `verbose`, and a
`model` override for a single solve.

## Steady and transient problems are separate types

`SIMPLE` is a fixed-point iteration, not a time integration, and the two are now
classified honestly:

| Algorithm | Problem type | SciMLBase root |
|---|---|---|
| `SIMPLE` | `SteadyIncompressibleProblem` | `AbstractNonlinearProblem` |
| `PISO`, `PIMPLE` | `IncompressibleProblem` | `AbstractODEProblem` |

Constructing an `IncompressibleProblem` with `SIMPLE` now throws and points at
the steady type. Code that dispatches on the problem type and does not care
which it has should use the `AnyIncompressibleProblem` union.

```julia
# before
prob = IncompressibleProblem(mesh, bcs, SIMPLE(); nu = ν)
# after
prob = SteadyIncompressibleProblem(mesh, bcs, SIMPLE(); nu = ν)
```

## Solver state is one flat vector

`IncompressibleState` now holds a single solution vector `u`, laid out as the
velocity block followed by the pressure block, with the velocity and pressure
fields as views into it. This is what the integrator advances and what symbolic
indexing reads.

`sol[:U]`, `sol[:p]` and `sol[:phi]` return independent `Vector` copies rather
than aliases of live solver state, so mutating a returned field no longer
corrupts the solution.

## Stepping interface

`init`, `step!` and `solve!` join `solve` on the exported surface:

```julia
integrator = init(prob; linear_solver = LUFactorization())
step!(integrator)                 # one SIMPLE iteration, or one time step
integrator.u[1] += 0.0            # inspect or modify state between steps
sol = solve!(integrator)
```

The integrator covers plain incompressible flow. Problems whose model carries
turbulence, thermal, radiation or combustion components are rejected by `init`
with an explanatory error, because those couplings interleave scalar transports
between the momentum and pressure stages; drive them with `solve`.

## Module structure and imports

The package is now organised into submodules — `Geometry`, `Numerics`,
`VertexConditions`, `Parabolic`, `Collocated` (with a nested `Physics`),
`Hyperbolic`, `FVMIO`, and `Experimental`. Research scaffolds live under
`Experimental` and warn once per session when used.

The top-level export surface was curated substantially. Names that are no
longer exported are still reachable by qualifying them
(`FiniteVolumeMethod.Collocated.some_internal`), and family-specific boundary
conditions are reached through their module (`Parabolic.DirichletBC`).

### Renames

| Old | New |
|---|---|
| `ParabolicDirichlet` | `Parabolic.DirichletBC` |
| `ParabolicNeumann` | `Parabolic.NeumannBC` |
| `ParabolicRobin` | `Parabolic.RobinBC` |
| `ParabolicKEpsilon` | `Parabolic.KEpsilon` |
| `ParabolicTurbulentWall` | `Parabolic.TurbulentWall` |
| `parabolic_to_odefunction` | `to_odefunction` |
| `parabolic_to_linearproblem` | `to_linearproblem` |
| `ParabolicPeriodicBC` | `StructuredPeriodicBC` |
| `parabolic_sound_speed` | `Numerics.sound_speed` |
| `parabolic_compute_friction_velocity` | `rough_wall_friction_velocity` |

The first seven still resolve through deprecation aliases in v4.0; they will be
removed in a later release. The last three were removed outright, having had no
consumers.

`ParabolicNonlinearDirichlet`, `ParabolicNonlinearNeumann`,
`ParabolicNonlinearRobin` and `ParabolicCoupledBC` were deleted: they were
declared but never reachable from any solver path.

## Solutions and return codes

`retcode` is a `SciMLBase.ReturnCode.T` rather than a bare `Symbol`, so
`SciMLBase.successful_retcode(sol)` and the rest of the return-code machinery
apply.

`IncompressibleSolution` deliberately does **not** subtype
`SciMLBase.AbstractODESolution`. That contract implies a real time axis and an
interpolating `sol(t)`; the steady solve has no time axis, and the transient
solvers store snapshots only every `save_every` steps rather than a dense
trajectory. Symbolic access is provided through `SymbolicIndexingInterface`
traits instead, which is the part that can be honoured exactly.

## Hyperbolic solvers

`HyperbolicProblem`, `HyperbolicProblem2D` and `HyperbolicProblem3D` now share
an `AbstractHyperbolicProblem` root under `SciMLBase.AbstractSciMLProblem`.
They are deliberately *not* rooted at `AbstractODEProblem`: they are converted
to an `ODEProblem` by `sciml_problem(prob)` rather than being one.

`solve_hyperbolic` and `solve_hyperbolic_imex` are internal; use `solve` on the
problem, or `sciml_problem(prob)` when you need the underlying `ODEProblem`.
`solve_amr` remains exported, since dynamic regridding has no SciML equivalent.
